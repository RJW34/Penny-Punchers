# Private two-peer rollback

Exactly two peers own one seat each. Offline play supports two local devices. There is no account service, matchmaking, spectator/team protocol, automatic UPnP or public firewall configuration. Development socket tests bind loopback; the explicit private LAN flow uses the address entered by the user. Socket evidence on one computer does not close the two-physical-machine gate.

The implemented bounded UDP transport carries redundant inputs and acknowledged/retransmitted control messages. Transport alone is not rollback [SRC-07]; deterministic save/load and frame execution remain separate requirements [SRC-06]. Shop-only v2 uses wire magic `0x324c5355`, hello protocol 3 and preparation commit/reveal version 2. Handshake checks build, canonical content, session, configuration and seat; legacy/assisted/training peers are rejected. The lobby negotiates fighters and host stage. Supers are acquired in each round's shop, never granted by lobby selection.

Reliable controls cover lineup readiness, preparation, start, pause/resume, leave, confirmed settlement and mutual same-lineup rematch. Input frames are seat-owned with bounded sequence/range/history acceptance. No packet accepts a trusted balance, cost, bonus, damage, health or client timestamp as simulation time. Malformed/oversized payloads and forged seats are rejected.

Each plan has at most six distinct products, a zero compatibility reserve, canonical content hash and quoted price. The Core validates fighter, semantic slots, count, ownership product type, budget and shop cap. Peers first commit the hash of the canonical plan plus random nonce, then reveal and validate preimages. Only two valid plans can trigger the atomic debit; visual reveal/countdown follows. The 15-second local deadline submits the last valid draft. An invalid edit cannot replace it; its initial value is the empty cart. False/mismatched reveals abort. This prevents casual last-mover shopping advantage without claiming trustless anti-cheat.

Default input delay is 2 ticks, prediction cap 8 and snapshot history 240. Remote held direction/buttons predict from the latest known input and edges derive from that stream. A correction restores the preceding snapshot and replays all affected ticks, including input/charge state, round ownership, one-use super receipts, source roots, eligible defense clocks and capped pending skill rewards. Banks stay fixed during combat. Local reversible action/jump/dash presentation changes have stable Add/Confirm/Cancel identities; contact/use/reward/results are confirmed before public presentation/history.

An exhausted prediction window stalls the simulation explicitly. Confirmed canonical hashes are compared every 60 ticks; an unresolved mismatch produces a bounded diagnostic and aborts instead of rewriting money or inventing a winner. Settlement requires the confirmed terminal tick/hash, is atomic/idempotent and cannot follow a speculative KO. Both peers replay their confirmed input/transaction log into complete recordings.

Pause negotiates a shared confirmed tick/hash barrier. Paused peers continue bounded heartbeat traffic, so an open menu does not cause an idle timeout. Resume requires mutual acknowledgement and a 120-tick neutral countdown. Leave is reliable and invalidates the session without a predicted payout. Rematch requires both players; changing seats/fighters requires a fresh private lobby. The UI reports rollback/stall counts; a live measured RTT estimator is not implemented.

## Evidence and limits

Run actual two-process full matches at 0/50/100/150ms RTT, with representative 0/20ms jitter, 0/1/3% loss and bounded duplication/reordering. Require identical final canonical bytes, replay bytes and typed round receipts. Include late parry retracting a predicted prepaid-super KO, startup/reward rollback, incompatible handshake/content, malformed replay/packets, forged seats, disconnect/pause/leave/rematch controls and a real automatic shop timeout. The current App tests and socket matrix are separately recorded in `reports/SHOP_ONLY_APP_REVIEW.md`; that report binds the actual tested content identities. Do not interpret four representative profiles as all possible fault combinations or human latency quality.

Graphical two-peer films, actual Windows/Linux execution and two physical LAN machines are distinct evidence scopes. Missing hardware/human checks remain explicit rather than being inferred from loopback success.
