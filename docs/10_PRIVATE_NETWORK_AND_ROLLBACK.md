# Private 1v1 rollback, not public services
Exactly two peers and two seats. One human local seat per network peer. Local offline play supports two devices on one machine. No team authority, spectator protocol, four-seat lobby, matchmaking, account or router automation. Bind loopback by default in development; explicit Host LAN can bind a selected LAN interface. No automatic UPnP, public firewall change or credential collection.

Use Godot/ENet or another vetted transport for bounded messages. Transport is not rollback [SRC-07]. GGPO's documented model requires deterministic state save/load and frame execution [SRC-06]; implement those contracts explicitly whether integrating that library or writing the bounded session layer. No claim of rollback from merely setting an input delay.

Reliable control: protocol/content/build handshake; seat ownership; character/art select; preparation plan versions and commits; match start; pause/disconnect; confirmed terminal transaction. Input stream: seat-owned digital input frames with redundant recent samples, sequence/range limits and bounded future-window acceptance. Never accept client wallet, cost, health, damage, timestamps as elapsed combat time, or cross-seat input injection.

Preparation: peers commit a hash of canonical plan+random nonce before reveal, then exchange the preimages and validate against opening balances. Bound deadlines, message sizes and invalid-plan handling. Cryptographic commitment initially sends only hashes and does not debit money. After both preimages validate, run the atomic economy commit, then show the visual reveal. Do not charge one player early while still waiting for the other plan. This prevents a casual last-mover reveal advantage; it is not anti-cheat-grade trustless competitive infrastructure. A last valid empty plan is acceptable on timeout before commitment; a false/mismatched reveal aborts cleanly, not silently grants purchases.

Default input delay2, prediction window8, snapshot history240. Predict remote direction/held buttons from last known input; derive edges from the predicted stream so held paid attacks do not repeatedly execute. On changed remote input restore the preceding snapshot and resimulate every tick through current prediction. Include scalar wallets, floors, command state, action ordinals and receipt history. Deduplicate/cancel audiovisual events on corrected timelines; avoid repeated super sounds and lingering false KO panels.

If confirmation lag exceeds eight frames, stall explicitly until input arrives; do not increase unbounded prediction or let the combat timer continue alone. Compare canonical hash every60 confirmed ticks. On mismatch collect a bounded desync dump (state, recent input, build/content versions), attempt at most one explicit resync, then abort honestly if unresolved. Resync cannot mint credits, reapply preparation or declare a fake winner.

No score/payout/shop transition on predicted KO. Confirm the terminal tick first. End-state settlement is reliable, atomic and idempotent with matching terminal hashes; delayed duplicate messages cannot repay either player.

## Required network evidence
Run two actual processes communicating over sockets, complete a full economy match, capture both views and final matching hashes/receipts. Also run controlled traces with latency0/50/100/150ms RTT, jitter0/20ms, loss0/1/3%, duplicates and reordering. Report the behavior and tested limits rather than claim every network is smooth. Tests include late parry changing paid-super KO, reordered startup inputs, affordability changed by earlier rollback, disconnect during preparation and during paid startup, mismatched builds/content, malformed/oversized packets, forged seat and repeated settlement.

A loopback test proves two-process behavior, not a real network adapter/router test. The LAN device gate requires actual two-machine play. Finish loopback/fault-injection work even when a second physical machine is unavailable. Windows/Linux determinism is a separate cross-platform gate requiring actual runs or named external evidence.
