# Buyables: validation and release gates

This is a proposed test plan, not recorded balance data. Pair it with the expanded audit's comeback protocol. Do not mark any candidate balanced because its JSON validates or because a weak CPU failed to defend.

## Precondition: fix the audited foundations

The real controls/camera/input issues, rented-move practice access and CPU/lab capability gaps must be repaired before strategic conclusions. In particular, the existing laboratory's generic feint command and fixed lexical rental selection cannot evaluate this candidate catalog. The current exact item/move/roster counts and slot-index prices must become validated registries.

## Gate B1 — Complete free play

At zero credits, both fighters retain their baseline moves/defense. Exercise free anti-air, projectile contest, low/overhead/throw threat, movement and punish routes against ordinary and funded opponents. Not every disadvantage must be escapable, but no candidate may require its own paid counter-item for a functional neutral/defense game.

## Gate B2 — Transaction and identity

Test before/at/after cost, reserve boundaries, simultaneous plan locks, duplicate and conflicting receipts, late network reveal, invalid command/availability, interruption, throw, parry and termination. Restore predicted paid actions and fields. Every action incurs its documented fee once, never both rent and activation. All failed precommit checks cost zero. Publish content/ruleset/source identity per run; preserve old audit evidence.

## Gate B3 — Individual tactical value

For each of the 38 candidates, provide an intended-use input trace, a punish/defense trace, a base-kit alternative and an equally funded no-purchase comparison. Distinguish purchase selection, move reachability, deliberate policy usage, successful tactical consequence and opponent threat response.

A rental comparison begins with the same total credits. The buyer pays the real rental fee; the control keeps that money and can actually spend it. Do not compare a rented tool with a penniless dummy and call the purchase good.

Feints require human or a demonstrably appearance-reactive policy. A bot reading an action ID before a human could distinguish the tell invalidates the deception experiment. A bot that never uses the bought command invalidates the value experiment. Unused-but-respected threats may be useful, so activation count alone is not the verdict.

## Gate B4 — Synergy and abusive combinations

Prioritize pairwise interactions: launcher plus confirm art; command throw plus overhead; counter plus armor; reflection plus projectile; pulse return plus normal; major field plus shot; dive kick plus land recovery; install plus baseline target combo; microstep plus charge; feint plus reaction-sensitive bot. Same-slot choices never coexist.

Test large-bank repeats. At 3,600 credits, 900/1,200/1,500 supers allow 4/3/2 activations respectively before other expenses, with 600 left in the last case. No per-round ticket limit is added to hide bad pricing. Infinite or effectively unchallengeable loops need changes to the move/interaction/cost, not a hidden second gauge.

For fields explicitly test all simultaneous actor/projectile/field hit, block, parry, destruction, owner knockdown and round-end events, both seat orders. No unavoidable contradictory guard directions. Reject a field/teleport/armor design if ordinary defense has no intended response from representative neutral/setup states; do not add another mandatory buyable to fix it.

## Gate B5 — Catalog size and learning cost

Core trial pool: two choices per rental slot per fighter, eight baseline EX families and two conventional supers per fighter (24 catalog entries). Its purpose is to test the clearer shop and useful budget choices, not to shrink the existing production roster/art contract. Keep existing third arts usable in production while testing their proposed replacements separately.

Full library: four options per slot per fighter. With None included, each fighter has 125 nominal rental loadouts before affordability; three selected arts make 375. Do not present that configuration count as 375 distinct viable strategies. First measure comprehension, time-to-ready, accidental selections and repeated desire to rematch; then add advanced options in coherent waves. An item may remain out of the competitive pool if its test fails, while its design is retained as a candidate.

## Gate B6 — Comeback measurement

Freeze prices/moves for any payout comparison. Preserve the earlier 1–0 score-controlled wallet interventions and separate overall skill/score effects from economics. Track role-specific affordability, next-round liquidity, efficient-versus-wasted spending, cap clipping, zero-wallet chip and the first-round difference. Do not call the first-round winner's conversion rate excessive just because it exceeds 50%; the earlier score-only reference is 63.67% for fair independent decisive rounds.

No payout change is applied by this pack. The audit's [1200,1200,1500] loss schedule is a candidate experiment, not an approved live default. Do not silently combine that change with a 50% technique price reduction and then claim which treatment caused the outcome.

## Gate B7 — Human and technical release

After passing software scenarios, run controller-only selection/practice/full matches, actual physical devices, two physical computers and normal-speed video. Record what players thought each purchase did, what they intended to do, whether they executed it, whether the opponent noticed and whether the cost felt worthwhile. Small sessions find problems; they do not establish tournament balance.

Track original animation timing, offensive readability, contact geometry, input-to-cue latency, event-position consistency, freeze behavior and attribution of frame outliers. No historical passing art map proves new feints or install/field motion are readable.

A candidate is releasable only when its ID has executed behavior evidence, understandable UI, a free-kit comparison, credible counterplay and a bounded strategic test. Native absence or missing human feedback stays NOT_RUN, never becomes an invented pass.
