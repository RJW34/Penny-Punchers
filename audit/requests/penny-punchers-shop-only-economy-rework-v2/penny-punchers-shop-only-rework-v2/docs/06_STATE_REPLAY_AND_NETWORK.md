# State and private rollback
Keep the independent deterministic C# Core and existing Godot shell. This pack does not adopt a new network service or rely on a library magically fixing state. Rollback fundamentally needs complete save/restore and resimulation; GGPO's documented integration contract supports that principle, not a claim that this game already passes it.

Snapshots include ruleset/content/build IDs, bank, opening bank, exact cart/cost receipt, sorted licenses, round art, remaining super use, action ordinals and root inheritance, eligibility clocks, armed parry/frozen provenance, pending skill receipts, seen fact IDs, paid category counts, offensive/defensive dedupe decisions, terminal and settlement IDs. State must not depend on UI, callbacks, packet arrival order or OS clock for combat classification.

Predict purchases only after both commit/reveal payloads validate. During combat local simulation may predict skill receipts and super-use consumption. Corrected input restores the pre-tick snapshot, erasing wrong rewards/uses naturally. Never issue compensating cash transactions. Confirmed cosmetic reward IDs deduplicate sounds/popups; predicted presentation must be explicitly reconciled if used. Bank remains frozen regardless of predicted skill results. No network packet is allowed to say “add100 credits”; peers recompute from input history.

Extend match identity: fighters/rules locked at match setup; per-round shop can change super art. Do not require both peers to manually duplicate a legacy super selection before connecting. Quote full validated catalog hash and canonical product IDs in commitments. Hash pending receipts as well as scores so peers cannot agree on terminal health but disagree on skill payout. Future-round/duplicate/conflicting/out-of-order packets fail closed. Cap dedupe collections and reject enormous payloads. Do not let rejected-fact diagnostics create unbounded snapshot history.

Replays must execute the real new source: old direct-spend recordings cannot be reinterpreted simply by replacing a header. Preferred bounded deliverable: retain old files and reject them with clear version/upgrade wording; an optional isolated legacy player may be added later. Metadata such as build hashes never substitutes for rerunning modified combat/reward logic. Native Windows/Linux and two real process traces are required; physical two-PC certification remains separate.
