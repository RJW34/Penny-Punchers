# Authority, supersession and explicit defaults
## Binding user direction
The latest feedback overrides older direct-spend rules: money is used only in the buy period; EX must be bought, not automatically available; loadouts can adapt round by round; skillful counter-hits, anti-airs and perfect parries can earn money. Strict 1v1, Third Strike-inspired qualitative feel and original art remain. Nothing requires franchise source, exact arcade timings or a new engine.

## Superseded, not merely disabled
Replace active instructions asserting “EX is always in the kit”, “debit credits at startup”, “no combat income”, “never buy a super use”, and “super selection locked for the match”. The previous assistant's 38-entry buyables model is not user authority. This rework intentionally reverses those resource decisions. Historical documents/evidence remain intact and explicitly archived; never rewrite old tests as though they tested new mechanics.

## Resolved defaults (adjustable via a recorded decision)
Round rentals rather than permanent unlocks; two individual repeatable EX families maximum; one prepaid super activation maximum; any one eligible super may be selected in each shop; 15-second shop, 3-second reveal, 2-second countdown, 60-second fight, first-to-five points/max nine rounds; full free baseline; 600 start/3600 bank cap/2400 total shop cap; equal 1200 base win and tier-zero loss, loss tiers 1200/1200/1500; capped 50/75/100 skill rewards; two eligible-tick perfect timing. These are starting hypotheses, not already approved balance outcomes.

## Scope choice
Migrate every actual live move and system first. Baseline catalog = 26 purchasable products, not 26 mandatory new animations. The separate 38-entry library is retained as an economic adaptation of earlier proposals. Unimplemented install/barrier/branch/armor moves do not become required solely because they have design entries. Any of them already implemented locally must be preserved and migrated. Do not reduce the live roster or regress working audit fixes.

## Reconciliation order
Latest explicit feedback → accepted rework decisions → live implementation facts and audit corrections → candidate numeric data → new acceptance → old designs. Preserve current controls, camera, rollback, original presentation and tests unless a documented resource change requires a revision. A current canonical file is not authority to contradict the new request. Never claim a global-stat feature is authorized by this feedback.
