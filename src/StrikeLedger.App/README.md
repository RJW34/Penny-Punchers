# Application systems

This independent .NET assembly uses the same `StrikeLedger.Core.Simulation` as the native shell.

* `BotController` submits normalized inputs. Conservative/adaptive opponents observe visible state through a 12-tick delay and use captured seeded RNG. Repeated calls for the same tick return the same input. Passive/guard/jump/throw and the explicitly training-only parry script are also available.
* `TrainingSession` owns a training-flagged simulation, drill state, dummy recording/playback, and checkpoints. Reset restores the dummy's initial RNG, queued commands and relative clock. A checkpoint includes core state and dummy input/RNG state. The charge drill requires Vale. Training/assisted configurations cannot enter competitive replay or networking.
* `ReplayRecorder` records preparation, normalized inputs, startup debit receipts, confirmed settlements and next-round commands. Version 2 playback validates recorded wallet values, periodic canonical hashes and exact debit receipts. Seeking restores a complete checkpoint and resimulates subsequent commands. Import is bounded to 64 MiB, 120,000 commands and JSON depth 16; there is no executable payload or compression.
* `RollbackSession` holds 240 snapshots, predicts held input, caps prediction at eight ticks and defaults to two ticks of local input delay. Corrections restore every core field including wallets and receipts. Earlier corrected KOs truncate obsolete future snapshots/events. Only confirmed presentation events are released, once, through `DrainPresentationEvents()`.
* `PrivateMatchPeer` owns exactly one local seat and one expected remote endpoint. Its UDP transport uses ordered, acknowledged, retransmitted and deduplicated control messages plus redundant recent input samples. The handshake checks protocol, compiled Core/App identity, content, configuration, session and seat. Preparation uses SHA-256 commit/reveal with random nonces and atomic core validation. Matching confirmed terminal hashes are required before a single settlement. Pause and preparation retain one-second keepalives.

`PrivateMatchPeer.SaveReplay(path)` reconstructs a separate simulation from confirmed inputs and confirmed transactions. It refuses a terminal recording that differs from the live canonical state. It also exports economic JSON and CSV. No predicted KO receives a payout or enters the replay settlement log.

`StrikeLedger.NetworkLab --self-test` exercises rollback, late parry/earlier KO, full bot replay/seek, malformed replay and real UDP rejection, disconnect, and a 16-second healthy pause. It also proves success and neutral-input timeout failure for all 16 training evaluators. Those traces use actual player inputs, with explicit deterministic dummy actions and training position/health controls captured as canonical fixture snapshots. `tools/run_network_lab.py --matrix --configuration ExportRelease` launches two actual UDP processes for each documented fault profile using the export configuration, requires full-match canonical/receipt agreement, and validates both saved network replays.

The laboratory driver runs faster than presentation's fixed 60 Hz to stress prediction. Its stall count measures attempted advances while the prediction limit blocks, not rendered frames or a smoothness score. The tested four-profile matrix is explicitly listed in the result JSON; it is not every Cartesian combination. Loopback evidence does not satisfy two-machine LAN, hardware-controller, Linux-native or human-feel acceptance. These remain distinct external gates.

Desyncs produce a bounded state/input/version dump and abort without changing the economy. There is no automatic router/firewall configuration, account service, public matchmaking, spectator protocol or claim of anti-cheat security.
